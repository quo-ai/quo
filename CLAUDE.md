# Quo

Privacy-first on-device AI assistant. Every version lives in this repo; each app is its own npm project (run commands inside its folder):

- **`apps/mobile/`** — phone apps (Expo / React Native). Details below; paths in that section are relative to `apps/mobile/`.
- **`apps/web/`** — Quo Web (Vite + React, wllama in the browser) and its API (`server/`, plain Web Request → Response; relative imports carry `.js` extensions so they run as native ES modules). `npm run dev`, `npm run typecheck`, `npm test`; hosting, environment variables and self-hosting in apps/web/README.md; end-to-end encrypted sync in apps/web/SYNC.md. Live on Vercel (`quoai-app`, Neon Postgres) via `bash apps/web/scripts/deploy.sh`.
- **`apps/desktop/`** — Electron app that serves a Quo Web build (`../web/dist`) from `app://quo` and runs models in a native llama.cpp `llama-server` process (pinned in `engine.lock.json`); see apps/desktop/README.md (`npm run fetch:engine`, `npm run dev`, `npm test`, `npm run smoke`). Releases come from `desktop-v*` tags.
- **`website/`** — static site (quoai.vercel.app). Document pages (privacy, terms, support, brand, 404) are generated by `website/scripts/generate-pages.py` from index.html's header and footer; edit the script, not the pages. Deploy with `bash website/scripts/deploy.sh`.

## Phone apps

Privacy-first on-device AI chat app. Expo SDK 57 / React Native 0.86 (New Architecture), llama.rn for local GGUF inference, single lifetime IAP (`quopremium`). Android ships a bundled starter model via Play Asset Delivery.

### Commands

- `npm run typecheck` — tsc, strict mode; must stay clean
- `npm test` — jest (jest-expo preset); pure-logic tests, native modules mocked in jest.setup.js
- `npm run lint` — 0 errors required; ~90 react-hooks v6 warnings are a known gradual burn-down (see eslint.config.js)
- `npm run android` / `npm run ios` — local dev build (Android emulators need an arm64 image; x86 is not built)
- `npm run sandbox [-- build|start|logs|shell|down|clean]` — Linux: Android dev loop in a rootless podman container (scripts/android-sandbox.sh, scripts/sandbox/Containerfile) on a USB phone; repo mounted read-only, writable state in podman volumes. Fedora needs `container_use_devices` SELinux boolean on. Use `build` after native/dependency changes; JS changes hot-reload
- `npm run ios:release` / `ios:release:upload` — App Store archive/upload (macOS only; see docs/ios-release.md in apps/mobile)
- `npm run fetch:starter-model` — downloads the ~530MB starter GGUF into the Android asset pack (release builds; runs automatically on EAS via `eas-build-post-install`)

### Architecture

- `app/` — expo-router. Root layout gates: AppLoading → ModelSelectionScreen (onboarding, outside the router) → `(drawer)` group (Chat `index`, Settings).
- `contexts/ChatContext.tsx` — central store: conversations, model lifecycle, streaming, tool loop, context compression, persistence. `contexts/PremiumContext.tsx` — entitlement/paywall.
- `services/` — singleton modules (`llmService`, `downloadService`, …) with manual listener-set pub/sub. Pure llm logic lives in `services/llm/` (prompt, tokens, compression, params); shared resumable-download helper in `services/fileDownload.ts`.
- `components/settings/`, `components/message/`, `components/onboarding/` — section/piece components for the three big screens.
- `constants/premium.ts` — single source of truth for PREMIUM_FEATURES, FREE_TIER_LIMITS, price fallback (PremiumContext re-exports for UI imports). `constants/models.ts` — model catalog incl. per-model settings, mmproj, draft models.
- Styling: plain StyleSheet + tokens from `constants/theme.ts` (light and dark palettes that follow the device setting). No tailwind/nativewind.

### Critical gotchas

- **Hexagon DSP is disabled in four places** (crashes on non-Qualcomm devices). The list is in `plugins/withLlamaFix.js`'s header comment — revisit all four on any llama.rn bump.
- `scripts/apply-native-patches.js` (postinstall) is the single source of truth for node_modules patches; it throws loudly when a dependency bump invalidates a patch — fix the patch, don't delete it.
- Model files must stay uncompressed for mmap: `noCompress += ['gguf']` in app/build.gradle. The Android starter model is a **fast-follow** Play Asset Delivery pack (`android/starter_model_pack`): Play downloads it right after install and it's loaded in place from the pack's file path via the local Expo module `modules/asset-packs` (no copy). First launch follows the pack's progress (`deliverStarterPack` in `services/bundledModel.ts`); installs without the pack (sideloaded/dev) fall back to the HF download. Test the real flow with `npm run sandbox -- bundle` (bundletool local testing); verify app *updates* on the Play internal track — local testing can't.
- Downloads are validated by size (95% of expected). Never accept a download on `result.uri` alone — truncated GGUFs pass existence checks and crash at initLlama. `isModelFileValid` (services/llm/paths.ts) is the one validity rule (≥95% of catalog `sizeBytes` + GGUF magic); catalog `sizeBytes` must be exact byte counts. Downloads/copies go to `.tmp`/`.part` and are moved into place only after validating.
- Storage is one AsyncStorage row per conversation + an index key (Android CursorWindow ~2MB limit). Don't reintroduce a single-blob write. `saveConversations` never deletes rows — removal is explicit via `deleteConversationRows`/`clearConversationRows`. Recall vectors live in files under `documentDirectory/recall/`, not AsyncStorage.
- llama.rn ignores the token callback's return value: native work only stops via `stopCompletion()`. `llmService.generate()` serializes completions (a new one aborts and awaits the previous) and streams the **full** visible text each update, not deltas; never `release()` a context while `isCompleting`.
- Streaming text lives in `StreamingContext` (`useStreaming()` → `{content, conversationId}`), not in `useChat()` — keep it out of the main context so token updates don't re-render the app. ChatContext init waits for PremiumContext to finish loading (running as "free" first used to delete premium users' chats).
- Model selection is persisted only after a successful load; a pending-load marker detects OOM-kills during load and falls back to the starter on next launch (contexts/chat/useModelLifecycle.ts).
- Do not run `expo prebuild` casually for **Android** — `android/` contains hand-maintained customizations (asset pack, signing helper, gradle heap/task tweaks). **iOS is the opposite**: `ios/` is not committed (gitignored); it's generated by `npx expo prebuild -p ios` (`npm run ios` and `npm run ios:release` do this). All iOS config — usage strings, entitlements, Firebase file, static frameworks — lives in app.json and the config plugins; never hand-edit the generated project.
- iOS Firebase needs the real `GoogleService-Info.plist` at repo root (gitignored; see the committed .example). Without it, iOS analytics/crashlytics/remote-config silently no-op.
- **Quo Sync on the phone** (`services/sync/`, UI in `components/settings/SyncSection.tsx` and the `components/settings/sync/` folder). Chats are read and written *through the chat context* (`services/sync/bridge.ts`, `contexts/chat/syncBridge.ts`), never straight to AsyncStorage: `conversationsRef` in ChatContext is the synchronous source of truth and `setConversations` is a wrapper that updates it first, so a sync write can't land on top of an edit made in the same moment (it checks the chat's fingerprint and retries). Sync deletions and the free tier's trimming are `quiet` (`deleteConversationRows(ids, { quiet: true })`), so they're never announced back as user deletions, and `markSyncApplied` stops what sync wrote being re-uploaded as an edit. The key and sign-in token live in `expo-secure-store`; both it and `expo-crypto` are native modules, so the first release with Sync needs a new native build, not an OTA update. There are deliberately no purchase flows for Sync in the app (Play Billing policy); it only tells people the plan comes with their Quo account.
- Both platforms bundle the starter model (Android: fast-follow Play Asset Delivery pack; iOS: app-bundle resource via plugins/withIosBundledModel — canonical file in gitignored assets-native/bundled-models/, fetched by scripts/fetch-starter-model.js). Deliberate gap: iOS pauses generation when backgrounded (Android keeps going behind an ongoing notification).

## Web and desktop gotchas

- **Services that aren't set up answer `503 setup_required`, they are not hidden.** Sign-in, paid models, purchases and Quo Sync stay visible in the app and show a plain "not set up yet" message (`SETUP_MESSAGES` in `apps/web/server/env.ts`). Don't re-add code that hides them when `features.*` is off.
- **One `InferenceEngine` interface, two engines** (`apps/web/src/engine/`): wllama in the browser, and `nativeEngine.ts` in the desktop app (chosen at load time by `window.quoDesktop.engine`). The desktop catalog (`DESKTOP_MODELS` in `catalog.ts`) is separate from the browser's; model files there are always stored as `model.gguf` (+ `mmproj.gguf`).
- **Desktop engine builds are official llama.cpp releases**, not the npm bindings (`@fugood/llama.node`, `node-llama-cpp`): the bindings ship generic x86 builds that ran ~3x slower on CPU. Voice stays in the renderer (Transformers.js) because the native whisper bindings ran at 0.2x real time on CPU. Update llama.cpp only through `engine.lock.json` and `npm run check:engine` (apps/desktop/README.md). macOS universal builds need `mac.x64ArchFiles` for the engine folders.
- **The WebAssembly speech runtime is hosted by the app, never a CDN** (`voice/whisper.worker.ts` sets `wasmPaths`; Transformers.js defaults to jsDelivr, which would break the privacy promise). `dropUnusedSpeechRuntimes` in vite.config.ts removes the 27 MB variants nothing loads.
- **Quo Sync's crypto format is a public contract** (`src/sync/crypto.ts` on the web, `services/sync/crypto.ts` on the phone, SYNC.md): changing the key derivation, AAD or blob layout without bumping the version byte strands every user's cloud copy. `src/sync/__tests__/vectors.json` holds records both implementations wrote and must read; the engine is tested end to end against the real server code (`src/sync/__tests__/engine.test.ts`), and the phone against the web in `apps/web/interop/` (`npm run test:interop`). Keep all three passing.
- **The sync engine is shared, not duplicated.** `engine.ts`, `merge.ts`, `kinds.ts`, `wire.ts` and `recovery.ts` are the same files in `apps/web/src/sync/` and `apps/mobile/services/sync/` (the phone app can't import from outside its folder). Edit the web copy, then `node scripts/check-shared-sync.js --fix`; CI fails if they differ. They must stay free of platform globals (no `crypto`, no DOM, no React Native).
- Attachments' contents (images, document text) are never synced, only their names (`toWire` in `src/sync/adapters.ts`, `toWireMessage` in `services/sync/convert.ts`). The long-chat summary and other derived data never leave the device.
- Chat ids are the server's record ids unchanged; every other kind is prefixed (`memory:<id>`). An old client that doesn't send `kinds` to `pull` gets chats only. Don't change either without a plan for clients already out there (desktop 1.1 is).
- **Cloud models** are listed in `apps/web/server/cloudModels.ts`; clients fetch them from `/api/models`. Every id must exist on OpenRouter (check against https://openrouter.ai/api/v1/models, which also has current prices and release dates), and prices are what OpenRouter charges. `tier: 'frontier'` models are the flagship ones, shown in the picker behind a lock. A model is locked until the person is signed in and has credits for a typical message (`lockOf` in `src/cloud/access.ts`: one rule, used by the picker and `App.choose`, which opens the paywall instead of switching). Don't hide paid models when accounts aren't set up: they stay visible and the paywall says so. Figures the app shows are copied from the server: plan prices (`src/cloud/prices.ts` ↔ `server/billing.ts`) and the trial (`TRIAL` ↔ `TRIAL_CREDITS` in `server/credits.ts`); change both together.
- **Code mode (the coding agent) is security-critical; read `apps/desktop/README.md` → Code mode before touching it.** The rules that must not erode: the project folder is chosen only in a native dialog, or is a new empty folder the app itself makes under `Documents/Quo Projects` (`workspace.js`: the page supplies only a name, reduced to `[a-z0-9-]`), and the page holds only an id; edits and commands are approved only in native dialogs from the main process (never a button in the page); every model-supplied path goes through `resolveInside` (a path outside the project is read only after a native approval of that folder, and then against that folder as its own root: `external.js`; the changing tools never take one); secrets files are unreadable and well-known token formats redacted; network access is the GitHub zip download and the web tools (see the next bullet); the tool list and system prompt are owned by the server or, for the user’s own API keys, the app (`shared/agentTools.ts`). Add a tool in three places that must agree: `shared/agentTools.ts` (schema), `desktop/src/agent/session.js` (`TOOL_NAMES` and dispatch), `web/src/agent/describe.ts` (what the chat says), and give it a test that tries to abuse it. The sandbox model (`openrouter.ts` stand-in) can run the whole loop without an API key. Anything that runs without asking (`commands.js`) must be *recognised*, never filtered: widen that list only with a test that tries to abuse the new entry (writes, reads outside the project, secrets, chaining, Windows). Settings that can run commands (`isProtectedPath`) stay read-only to the agent.
- **Commits made by Quo (`apps/desktop/src/agent/commit.js`) are security-critical and credit Quo as co-author.** The app, not the model, writes the `Co-Authored-By` trailer (its address is the `quo-ai[bot]` GitHub App's id; change both together), only when the "Credit Quo in commits" setting is on (default), and every commit goes through its own native approval dialog with no "for this session" option. Keep: explicit file list committed with `--only`, `--literal-pathspecs`, secrets/protected paths refused, no git identity set or invented, hooks-path edits refused, never push. Tests in `test/agent/commit.test.js` try to abuse each.
- **Background commands and the `task` helper are bounded versions of tools that already exist.** Background commands (`apps/desktop/src/agent/background.js`) start only after the same native approval as any command, are limited in number, scrubbed like other commands and killed when the Code session ends. The helper (`apps/web/src/agent/subagent.ts`, `role: 'explore'` in `server/chat.ts`) can only ever have the reading tools: the server ignores the tools the app asks for in that role. Keep both limits when changing either, and test the abuse. Long-session summaries (`apps/web/src/agent/summarize.ts`, server role `summarize`) get no tools, are carried as labelled notes inside the person's message, and fall back to dropping old output.
- **What models are told about their surroundings** (`apps/web/shared/environment.ts`) never includes where the person is: only the clock's offset from UTC and the language (no region), no time zone name, no IP lookup. Capabilities listed must match the tools or abilities the chat really has. For Quo's cloud models the server builds the note from its own clock and the model list, and checks each field the app sends. Keep the note at the end of the prompt (the fixed part before it stays cacheable).
- **The user's own API keys are security-critical** (`apps/web/src/providers/`, `apps/desktop/src/providers/`; see "Your own API keys" in `apps/desktop/README.md`). Must not erode: the page never reads a key back (`providers:list` returns the last four characters); main decides where a key goes (built-in addresses in `registry.js`, custom servers stored in main, editing an address deletes its key); only the chat call and model list, by exact path; headers come from main; redirects are refused; errors never hold a key; keys are encrypted with `safeStorage` or kept in memory, never in the clear. A new provider goes in both registries (a web test compares them). Browser keys stay in localStorage, never synced. Treat these models like cloud models for privacy: no memories, no attachments.
- **Web search (`apps/desktop/src/web/`) is security-critical** (see "Web search" in `apps/desktop/README.md`). Must not erode: the model may open only an address the user wrote, a search returned, or a page it read links to, exactly as written (`sessions.js`); only public addresses, checked at connect time and on redirects (`guard.js`); no cookies, GET only, limits; queries are cleaned of secret formats; search keys are stored and never read back like provider keys. Offline-model chats start with Web off on purpose (offline stays offline; web tools cost photos, documents, thinking). Never route a Quo-paid search through the free model.
- **Anything added inside `.composer-wrap` must set `pointer-events: auto`**: the area ignores clicks except on its own parts (it floats over the messages), and a banner without it looks fine and does nothing. Motion lives in `styles/crt.css` (dither masks, stepped); new animations must stop for reduced motion.
- **Connection awareness** (`apps/web/src/net/`): switching only ever goes *toward* the offline model, never to a cloud one; coming back online only offers to return.
- **Code mode on offline models** (`apps/web/src/agent/local.ts`, `capability.ts`, `support.ts`): sessions are *compact* (`COMPACT_LIMITS` in `desktop/src/agent/session.js`) and the engine loads with `AGENT_CONTEXT`; keep tool results small, a small window is the main failure. Ratings (`agent` in the catalog) are judgment and only decide whether to ask first; they never loosen approvals. Don't pass the catalog's sampling to tool calls: the repetition penalties break code and JSON.
- **Memories (web and desktop)** live in the `memories` store of the same IndexedDB database as chats, opened only in `src/db.ts`: add a store by raising the version and adding an `oldVersion <` branch, never by recreating (`src/memory/__tests__/store.test.ts` upgrades a real v1 database). They go into the prompt of *offline* models only (`memoryPrompt`, in `ui/Chat.tsx`); never add them to a cloud model's prompt: that would send personal facts to a third party, against what the app promises.
- **Who is signed in is decided by the database, not just the token** (`identify(db, request)` in `server/identity.ts`, async): the token must be genuine and unexpired, the account must exist, and the session must be newer than `users.sessions_valid_after` (set by `POST auth/signout-all`). Never read a user id straight from the token (`readSession`); a signed-out request costs no query. Sync routes also pass through a per-account call limit (`takeSyncCall`).
- **Account deletion exists and must keep working** (`POST account/delete`): Google Play requires in-app deletion for any app that lets people create an account. If you add a table with a `user_id`, add it to `handleAccountDelete`.
- `SYNC_API_ORIGIN` (`apps/mobile/constants/sync.ts`) is the hosted API's address; it moves with the domain, alongside `WEB_APP_URL`, `API_ORIGIN` and `LINKS.webapp`.

## Keeping the repository clean

- **Nothing sensitive is committed.** `scripts/check-secrets.js` (CI runs it with `--history`; the pre-commit hook is `scripts/hooks/pre-commit`, turned on once per clone with `git config core.hooksPath scripts/hooks`) blocks secrets files by name, secret formats, home folders with a real name in them and email addresses that aren't ours. It never prints what it found. Tests that need a fake key or address build it at run time (`'gh' + 'p_'…`), because the scanner is strict on its own tests too. The root `.gitignore` covers secrets everywhere.
- **No source file over 500 lines** (`scripts/check-structure.js`, in CI). Older long files (mostly in `apps/mobile`) are listed there at their current length and may only shrink; when one drops under the limit, take it off the list. Split by what the code does, one concern per file: see `apps/desktop/src/agent/files/`, `apps/web/src/ui/chat/` and `apps/web/src/styles/` for the pattern. Tests follow the code (`apps/desktop/test/agent/`), with shared setup in a `helpers.js`.
